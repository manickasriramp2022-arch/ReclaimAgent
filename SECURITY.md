# Security notes

ReclaimAgent is an offline batch tool, not a service. It listens on no port,
authenticates no one, and stores no credential. That removes most of the attack
surface a payments system normally carries, and it makes the surface that *does*
exist easy to state precisely. This document states it, because a control nobody
wrote down is a control that survives only until the next refactor.

## What is trusted, and what is not

| Input | Trusted? | Why |
| --- | --- | --- |
| CLI flags, `--out-dir`, `--config-dir` | Yes | Supplied by the operator running the command. |
| `ANTHROPIC_API_KEY` and other env vars | Yes | Same process boundary as the flags. |
| `config/*.yaml` | Yes | Repository content, reviewed like code. |
| **The batch JSONL file** | **No** | Nominally generated by `reclaim generate`, but the format is documented and `--batch` accepts any path. Treat its string fields as attacker-controlled. |
| **The LLM's `rationale`** | **No** | Free text from a model, generated in response to a `decline_description` that itself came from the batch. |

The two untrusted sources share one sink that can execute: `out/report_<run_id>.html`,
which a reviewer opens in a browser.

## Controls

**Every batch- and model-derived string is HTML-escaped before it reaches the
report.** `report.py:_esc` and `charts.py:_esc` both wrap `html.escape`, and every
interpolation of a non-numeric value goes through one of them — including the
audit event `detail` field, which is where the model's rationale lands
(`engine.py`, `detail=classification.rationale`). `tests/test_report_escaping.py` holds
this up: it poisons a
`case_id` in the batch and a rationale from a stubbed model, renders a real
report, and asserts both that no tag-forming sequence survives *and* that the
escaped form is present. The second assertion is the load-bearing one — without
it the test would pass just as happily if the field stopped being rendered at
all. Deleting either `_esc` call makes it fail.

**The report is self-contained.** No script, style, font, or image is fetched
from anywhere; the charts are inline SVG with a `<title>` hover layer and no
JavaScript. A report that fetches nothing cannot leak the run it describes by
fetching. `test_report_escaping.py` and `test_charts.py` both assert this.

**Config is parsed with `yaml.safe_load`** at both call sites (`config.py`,
`ablation.py`). No `yaml.load`, and no `eval`, `exec`, `pickle`, `marshal`,
`os.system`, `subprocess`, or `shell=True` anywhere in `src/reclaim`.

**The API key is read from the environment and passed straight to the SDK
constructor** (`classify.py`, `AnthropicClient.__init__`). It is never interpolated into
a log line,
an audit event, an error message, or the report; error text names the variable,
never its value. `.env` is git-ignored, `.env.example` carries a placeholder, and
`test_repository_ships_no_secrets` fails the build if a key-shaped string is
committed. CI never sets the key, so every CI run proves the offline path works.

**Non-test data is refused at construction.** `FailedTransaction` validates
`environment == "test"` and raises otherwise (`models.py`, `_must_be_test`), so a batch
file claiming to hold live transactions cannot be loaded at all.

**The audit log is append-only and hash-chained** (SHA-256, `prev_hash` /
`event_hash`). This is an integrity control, not a confidentiality one: it makes
after-the-fact edits detectable by `reclaim verify-audit`, which runs in CI. It
does not stop anyone who can write the file from rewriting the whole chain — an
append-only store would be the production answer, and is out of scope here.

## Out of scope, deliberately

No authentication, authorisation, session, or transport security, because there
is no service to secure. No secrets at rest beyond the operator's own `.env`. No
protection against a local user who can already write to `out/` — at that point
they can edit the artifacts directly, and the hash chain only tells you they did.

## Review

A security review of the full diff was run before submission, covering injection,
deserialisation, path traversal, secrets handling, crypto, and XSS in the report.
It produced no HIGH or MEDIUM findings. It did surface the gap this document
closes: the escaping was correct everywhere and asserted nowhere, which is a
property held up by convention rather than by the build. It is now held up by the
build.
